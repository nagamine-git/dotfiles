# doc-writing

読み手が少ない労力で、必要なことを正しく理解できる文書を書くためのスキル。
対象は、人が読み返したり他人に渡したりする文書である。たとえば README、設計メモ、手順書、ADR、Issue や PR の本文、報告がある。
チャットでのその場の返答は、`~/.agents/AGENTS.md` の「回答の書き方」に従う。このスキルの数値は目安であり、上限ではない。

## 根拠にしている考え方

| 考え方 | 要点 | この文書での使い方 |
|---|---|---|
| 認知負荷理論 (Sweller) | 理解に使える作業記憶は限られる。内容そのものの難しさ (内在的負荷) は変えにくいが、書き方が生む余計な負荷 (外在的負荷) は減らせる | 構造・用語・順序を整えて、余計な負荷を減らす |
| 作業記憶の容量 (Cowan 2001) | 一度に保持できるのはおよそ 4 つのまとまり (チャンク) | 一つの文や段落で新しく出す要素を絞る。並べる項目は意味でまとめる |
| マルチメディア学習の原則 (Mayer) | 合図 (signaling)、分割 (segmenting)、一貫性 (coherence: 無関係な情報を省く) が理解を助ける | 見出しと強調で構造を示し、長い説明は区切り、関係の薄い話は削る |
| 画面の読まれ方 (Nielsen Norman Group の視線計測) | 画面上の文章は流し読みされ、各行・各段落の冒頭に視線が集まる | 結論や要点を、文書・段落・箇条の冒頭に置く |
| 公用文作成の考え方 (文化審議会建議、2022 年) | 一文を短くする。50〜60 字ほどになったら読みにくくないか意識する。一文の論点は一つにする。三つ以上の並列は箇条書きにする。図表には標題を付ける | 下の「文の長さ」と「箇条書きと表」の基準にする |

## 書く前に決めること

書き始める前に、次の 3 つを一行ずつ書き出す。決まらないうちは本文を書かない。

1. **読み手**:誰が読むか、その人が既に知っていること。
2. **読んだ後の行動**:読み手が読み終えて何をするか (判断する、手順を実行する、承認する、参照する)。
3. **結論**:一番伝えたいことを一文で。

## 構造

- **結論を先に置く**:文書の冒頭に、結論と読み手がとる行動を書く。経緯や調査の過程はその後に置く。
- **見出しは内容を言い切る**:「調査結果」ではなく「原因は X の設定漏れ」のように、見出しだけで要点が分かるようにする。
- **一つの節には一つの話題**:一つの節で扱う主題は一つにする。節が画面 1 枚を大きく超えるなら分ける。
- **段落の冒頭に要点**:各段落の最初の文で、その段落の要点を述べる。続く文は根拠や例にする。
- **同じものは同じ名前で**:一度決めた用語は言い換えない。同じものを別の名前で呼ぶと、読み手は別物かどうかを考えることになる。

## 文の長さと書き方

- **目安**:一文はおよそ 40〜50 字を中心にする。60 字を超えたら、二つの文に分けられないか見直す。SNS や通知のように流し読みされる文は、さらに短くする。
- **目安を下回りすぎない**:20 字未満の文が続くと、文と文の関係を読み手が補わなければならなくなる。短い文をつなぐときは、「そのため」「ただし」などの接続詞で関係を示す。
- **一文一義**:一文で述べる論点は一つにする。論点が変わるところで文を切る。
- **主語と述語を近づける**:長い修飾語は、別の文に移すか、述語の近くに置く。
- **否定を重ねない**:「〜しないわけではない」のような二重否定は避け、肯定の形で書く。
- **体言止めを並べない**:本文は完結した文で書く。体言止めや断片的な語の羅列は、表のセルや短いラベルだけで使う。
- **専門用語**:必要な用語に絞り、初めて出すときに短く説明する。略語は初出で正式名を添える。
- **数値と事実**:測ったもの、確かめたものだけを断定する。推測と未確認は、そうと分かるように書き分ける。

## 箇条書きと表の使い分け

| 形式 | 使う場面 | 守ること |
|---|---|---|
| 地の文 (段落) | 理由、因果、条件のように、文と文の関係が大事なとき | 接続詞で関係を示す |
| 箇条書き | 同じ種類のものを三つ以上並べるとき | 各項目の形 (文か名詞句か) をそろえる。一つの階層の項目はおよそ 3〜7 個にする。入れ子は 2 段まで |
| 番号付きリスト | 手順のように順番に意味があるとき | 一項目に一つの操作。結果の確認方法も書く |
| 構造化した箇条書き | 項目ごとに補足があるとき | 「**ラベル**:説明」の形にし、ラベルだけ読めば全体が分かるようにする |
| 表 | 複数の項目を、同じ観点で比べるとき | 観点を列、項目を行にする。セルは短く保ち、文章はセルに入れない。表の前に、表から読み取ってほしいことを一文で書く |
| 図 | 関係や流れ、構造を示すとき | 図だけで意味が分かるよう、標題と凡例を付ける |

箇条書きは、地の文で書くべき因果や理由を分断しやすい。「なぜそうなるのか」を説明する部分は段落で書く。

## 書いた後の点検

点検は次の順で行う。

1. **冒頭だけ読む**:冒頭の数行だけで、結論と読み手の行動が分かるか。
2. **見出しだけ読む**:見出しを順に読むと、話の筋が通るか。
3. **文の長さを測る**:次のコマンドで、長すぎる文と短すぎる文を洗い出す。数値は目安なので、引っかかった文を機械的に切らず、読みやすさで判断する。

   ```sh
   python3 - <file> <<'PY'
   import re, statistics, sys
   text = open(sys.argv[1], encoding="utf-8").read()
   text = re.sub(r"\A---\n.*?\n---\n", "", text, flags=re.S)  # frontmatter は除く
   text = re.sub(r"```.*?```", "", text, flags=re.S)  # コードブロックは除く
   lines = [l for l in text.splitlines() if l.strip() and not l.lstrip().startswith(("|", "#"))]
   sents = [s.strip() for l in lines for s in re.split(r"(?<=[。！？])", l) if len(s.strip()) > 1]
   lens = [len(s) for s in sents]
   if lens:
       print(f"文の数 {len(lens)}  平均 {statistics.mean(lens):.0f} 字  中央値 {statistics.median(lens):.0f} 字  60 字超 {sum(n > 60 for n in lens)}")
       for s in sents:
           if len(s) > 60:
               print(f"[{len(s)}] {s}")
   PY
   ```

4. **用語をそろえる**:同じものを別の名前で呼んでいないか。
5. **削る**:読み手の行動に関係しない経緯、言い訳、重複した説明を削る。

## してはいけないこと

- 形式を埋めるためだけに見出し、箇条書き、表を増やすこと。
- 一文を短くするために、主語、対象、理由、条件を省くこと。
- 確かめていない数値や効果を、断定して書くこと。
