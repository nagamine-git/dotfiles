# Daily Focus

本人の次の行動と、そのための時間を決める。既定は最大5件・各60分、Asia/Tokyoの当日9:00〜19:00。件数・長さ・時間帯の指定があれば従う。

## 候補を集める

- 対象組織・リポジトリのルールからタスクの正本を確認する。EFGの会社タスクはLinear、MusePassなど顧客案件はその組織の正本を尊重する。GitHub・Gmail・Slack「あとで」・Notionは、依頼や期限、最新状況を補う情報源として使う。
- 本人が行う具体的な判断・操作・作業を候補にする。担当者が本人というだけで本人の作業とせず、AIだけで進められる調査・実装・レビューを本人の作業枠として扱わない。
- 会社と個人のタスクを区別し、個人のタスクを会社の管理先へ移さない。`co-nect`関連は候補から除外する。
- 完了済みや情報通知を除き、現在の期限・状態・本人が行う次の一手を確かめる。取得失敗は「未確認」として情報源ごとに示し、取得済みの情報で進められる範囲を提示する。
- 同一課題と確認できるURLやリポジトリ付きPR番号で重複を統合し、出典URLはすべて残す。似た題名だけで統合しない。

## 優先順位を提案する

期限、放置した場合の影響、他の仕事を止めている依存関係、本人の具体的な行動を根拠に最大5件を選ぶ。固定の点数や重複ヒット数だけで順位を決めない。候補が少なければ埋め合わせない。

候補を「タスク / 本人が行うこと / 期限・状態 / 選んだ理由 / 出典」の表で示し、差し替え・除外を含めて本人に確認する。確認前にはCalendarへ登録しない。

## 確認後に時間枠を作る

- 既定のカレンダーアカウントは`tsuyoshi.nagamine@efg-technologies.com`。利用可能な公式ツールで対象カレンダーと権限を確認する。
- 登録前に既存予定と同じフォーカス枠の有無を確認し、対象時間帯の未来の空き時間へ優先順で入れる。予定を取得できなければ登録を止める。
- 名前は`[FOCUS #順位] タスク`を基本とし、説明に本人の次の行動・期限・出典URLを残す。
- 空きが足りなければ確保できる分だけ登録し、残りを未登録として示す。翌日へ自動で登録しない。
- 登録結果を確認して、作成済みの時間帯とリンク、未実行・失敗・結果不明を区別して報告する。結果不明の作成をそのまま再試行せず、重複を確認する。

過去のTOP5履歴は別ファイルへ保存しない。
