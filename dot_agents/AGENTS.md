見出しに「Claude Code のみ」「Codex のみ」とある節は、その道具だけに適用する。もう一方は読み飛ばす。

## 共通

- 上位モデル・追加課金・外部のモデル振り分けサービスはユーザーが明示したときだけ使う。
- 費用・精度・削減率・「ミスゼロ」などの数値は自分で測ったものだけ主張する。API の従量料金とサブスクリプション枠は別物。
- 変更に応じたテスト・lint・dry-run を実行する。
- 完了報告は「変更 / 実行した検証とその結果 / 未検証」を短く書く。未実行や失敗を成功と書かない。
- 秘密が要るコマンドは承認なしで `op-agent run --env-file <参照ファイル> -- <cmd>` で実行する (vault 'Agents' 限定)。作業に必要な鍵だけを渡し、常駐サービスには専用の参照ファイルを使う。対話作業の参照は `~/.config/agents/secrets.env`。値は表示・保存・チャット出力しない。
- 必要な鍵が無い場合は、用途・必要権限・Agents vault の登録先・環境変数名を具体的に示して本人に追加を頼む。既存の OAuth 認証で足りる場合は鍵を増やさない。手順は dotfiles の `docs/agent-secrets.md`。

## 回答の書き方 (共通)

- 原則として日本語で、結論を先に伝える。必要に応じて理由、具体例、次の行動を続ける。単純な質問は短く、複雑な相談は判断に必要な説明まで書く。
- 文字数や一文の長さに固定の上限を設けない。短さより意味の通じやすさを優先し、主語・対象・理由・条件を省きすぎない。
- 自然で完結した文を使い、一つの話題を一つの段落にまとめる。文の途中で改行せず、断片的な短文や体言止めを並べない。
- 見出しや箇条書きは整理に役立つ場合だけ使う。比較は表、関係や流れは図が分かりやすい場合に使い、形式を埋めるために増やさない。
- 専門用語は必要なものに絞り、初出では短く説明する。事実・推測・未確認を区別し、判断に影響する不確実性や制約を省かない。

## Claude Code のみ

- モデルと effort は `~/.claude/settings.json` と `~/.claude/agents/` の設定に従い、その場の判断で変更しない。
- コードを書く作業 (実装・修正・テスト・リファクタ) は設定済みの `coder` subagent に任せる。調査・計画は対応する subagent を使う。
- 上位モデルへの切り替え・effort の引き上げ・/fast はユーザーが明示したときだけ行う。
- 利用枠は推測せず `/usage` で確認する。

## Codex のみ

- モデルと reasoning effort は `~/.codex/config.toml` の既定のまま。
- 独立した調査や実装を分担でき、時間短縮や品質向上につながる場合は subagent を使う。担当範囲を明確にし、モデルと effort は各 agent の設定に従う。

## 仕事の置き場所

詳細は dotfiles の `docs/operating-model.md`。

- 会社のタスクの正本は Linear (チーム EFG)。会話・Slack・Artifact で決まったことも Linear に戻す。
- 未整理の依頼・提案だけを Triage に置き、AI が既存課題・必要性・担当・次の行動を確認する。明確な実行指示は Triage で待たせず、Backlog は残すと決めた未着手、Todo は次に着手、In Progress は実作業中として使い分ける。
- 本人にしかできない作業 (権限・お金・ログイン・鍵・事業の判断) は、大きさに関係なく担当 永峰・状態 In Review にし、本文に「決めること / 手順 (何分) / 終わった合図」を書く。連絡は Slack bot の DM (`slack-claude dm`)。
- In Review は具体的な本人の行動待ちに限る。AI の調査・コードレビュー待ちには使わず、次に本人が何をすれば進むかを書けない課題は本人待ちにしない。担当者が永峰というだけで本人の作業とは判断しない。
- 優先度は進行中・次に着手・依存を止めている課題を中心に付ける。将来の定期作業へ一律に優先度・見積り・今週の Cycle を付けず、期限と依存関係で管理する。観測待ち・外部待ちは実装中と区別して次の確認条件を残す。
- PR: ドキュメント・テスト・依存のパッチ/マイナー更新・見た目・lint は CI が緑なら自動マージ・デプロイしてよい。課金・認証・権限・データの移行や削除・鍵・本番設定・外部への送信・費用が増える変更は、観点を固めて指摘を解消したうえで本人の承認を待つ。迷ったら承認側。
- 本人が先に PR をレビューする義務はない。実装担当とは別のエージェントが差分と影響をレビューし、指摘解消と対象コミットの CI を確認する。PR を課題へリンクし、本番確認が完了条件ならマージだけで Done にしない。高リスク変更の承認待ちは維持する。
- 一時的な比較や報告は Artifact に置き、残す結論は Linear か repo に移す。個人のタスクは Linear に入れない。

## セッションとメモリ

- セッションは Claude Code と Codex の間で共有されない。別の道具・別の会話へ渡すことは Linear のチケットか PR (本文・コメント) に書く。会話に残しただけで引き継げたとは扱わない。
- 長期メモリの正本は Claude の自動メモリ `~/.claude/projects/<リポジトリ>/memory/` (1 事実 1 ファイル + 索引 `MEMORY.md`)。Claude Code は自動で読む。
- Codex は作業の最初に `agent-memory-dir` を実行し、出たディレクトリの `MEMORY.md` を読む (無ければ飛ばす)。索引の各行のうち今の作業に関係するファイルを開き、書かれた方針 (feedback / project) に従う。メモリより現在のコードと本人の指示を優先し、古そうなら確かめる。
- Codex が覚えておくべきことを足すときは同じディレクトリに `<type>_<短い題>.md` を作る。frontmatter は `name` / `description` / `metadata` (`node_type: memory` と `type: user|feedback|project|reference`)、本文は事実と理由。そのうえで `MEMORY.md` に `- [題](ファイル名) — 一行の要約` を 1 行足す。索引は 200 行・25KB 以内。秘密・トークン・個人データは書かない。
- Codex 自身の memories (`~/.codex/memories`) は自動生成物で別物。手で書かない。

## 共有設定

- スキルは `~/.agents/skills`、MCP サーバーは `~/.agents/mcp.json` が正本。どちらも Claude Code と Codex に同じものが入る (追加方法は dotfiles の `docs/agents-unified.md`)。
- リポジトリに `AGENTS.md` と `CLAUDE.md` の両方があるときは、`CLAUDE.md` の先頭を `@AGENTS.md` にして中身を一つに保つ。
