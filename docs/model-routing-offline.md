# モデル振り分けの未有効化案

この資料は `model-route-plan` のローカル提案・予約機能を説明します。
実行入口 `model-route` の現在の状態と予算確認結果は [model-routing.md](model-routing.md) を参照してください。
`model-route-plan` 自体にはモデル実行・HTTP・shell・秘密取得の実装はありません。
`execution_enabled` は `false` だけを受け付け、すべての出力が `ready_to_execute: false` です。

## 振り分けルール

| 条件 | 提案する経路 |
| --- | --- |
| 通常、異なる仮説での失敗が1回まで | 既存 Codex / OpenAI |
| 異なる修正仮説が2回以上失敗、または重要変更の独立レビュー | Opus 候補 |
| Fable の例外を明示 | Fable 候補 |
| Claude へ渡す内容が非機密と確認されていない | Codex 候補に留める |
| 分類結果不明・破損・タイムアウト・利用不能 | Codex 候補 |
| タスクの承認待ち・拒否、または安全上の保留・拒否 | 停止。別モデルへ送らない |

ローカルルールと分類器の結果が食い違う場合も Codex 候補に留めます。
分類器はローカルルールが許していないモデル選択を追加できません。
モデルIDは調査時の候補を固定しています。既存 CLI のモデルや effort を変更する処理はありません。

## Typesafe と入力制限

Typesafe は分類器であり、Codex/Claude の gateway ではありません。
現段階で Typesafe へ接続するコードはありません。`--classifier-fixture` はローカルの模擬応答を読むだけです。
将来の分類器入力候補は失敗仮説数・重要変更の独立レビュー有無・Fable例外有無の3フィールドだけです。
本文、コード、差分、パス、task ID、URL、認証情報は含みません。

入力は固定スキーマの列挙値・整数・真偽値・UUIDのみです。自由記述や未知のフィールドは拒否し、エラーでも値を表示しません。
分類器の自由記述・不正なJSON・未知のモデル名は利用不能として扱います。
原文を受け取って後からマスクする仕組みではありません。入力に原文を入れないことが前提です。

## 認証経路と費用

`claude_subscription` と `anthropic_api` は別の提案経路です。相互に自動切り替えしません。
サブスクリプション候補には、実行時の公式 CLI での認証・対象アカウント・追加クレジットOFF・残量の再確認が必要です。
この実装は認証や利用量を確認せず、模擬値を実行許可として受け付ける機能もありません。

API の初期予算は0です。模擬見積額が正の整数で、1回・UTC日次・UTC月次の上限内の場合だけ、ローカルの模擬予約を記録できます。
予算超過や見積なしなら Codex 候補に留めます。OpusとFableの予約は同じ上限を共有します。
この予約は**支出でも請求上限でもありません**。実請求・税・再試行・並行する別ツールの支出を追跡しません。
非ゼロ予算を入力してもモデルの実行はできません。
実接続には別途、具体的承認・provider側の上限・実費の精算処理が必要です。

## 重複防止と期限

明示したローカル状態ディレクトリだけに、UUID・入力のハッシュ・提案・UTC日/月・模擬予約額を記録します。
同一UUID・同一入力は前回の提案を返し、二重予約しません。入力やポリシーが変わった同一UUIDは拒否します。
排他ロックは非待機で、競合は失敗として返し、自動再試行しません。書き込みは一時ファイルから置換します。
壊れた台帳を自動で消去・再作成しません。重複防止記録を勝手に捨てないよう台帳の大きさも制限します。
状態ディレクトリは本人所有・0700、入力ファイルはサイズ制限のある通常ファイルだけです。

分類器のタイムアウト結果は Codex 候補へ戻し、ローカル計画も設定した期限を超えていたら予約前に停止します。
ロック待ち・通信待ち・外部プロセスはありません。ただし OS のファイルI/O自体に厳密な実時間上限を保証する仕組みではありません。
実モデルのタイムアウト・強制終了・曖昧な請求結果の扱いは、未実装の実行層で別途必要です。
この重複防止はローカル提案の予約用であり、外部APIの exactly-once 実行を保証しません。

## 外部アクセスなしの確認

この差分案のルートで実行します。

```sh
python -B tests/model-route-plan.py
python -B dot_local/bin/executable_model-route-plan \
  --policy docs/model-routing-policy.example.json \
  --task tests/fixtures/model-route-task.json \
  --state-dir /tmp/model-route-plan-review-state
```

2番目のコマンドは、指定した状態ディレクトリに提案の記録だけを書きます。同じ入力で再実行しても予約は増えません。
テストはすべて合成メタデータを使い、socket・subprocess呼出しがあれば失敗するようにしています。
APIキー、op-agent、既存認証ファイル、セッション原文、私有repoの内容は読みません。

## 実接続前の残差分

1. 接続先・対象アカウント・送信データの範囲・保存/保持・モデル・予算を具体的に承認する。
2. 既存 `claude-delegate` のサブスク検査は緩めず、承認した実行経路を別途レビューする。
3. Typesafeを使う場合だけ、匿名化した固定スキーマの要求と応答検証、実通信の期限・課金上限を追加する。
4. サブスク実行では追加クレジットOFFを直前に確認する。API実行では必要なキーだけの受け渡しとprovider側上限を設ける。
5. 実行直前の内容ハッシュ照合、単発実行の予約、タイムアウト後の不確実な結果・請求の照会と精算を実装する。
6. 既存 dirty changes を保持した差分レビュー後、対象を絞った chezmoi diff / dry-run と承認を経て反映する。

この案を既存repoに追加すると、対象を指定した chezmoi apply で `model-route-plan` を配置できます。
自動起動やscheduleは含みません。配置はam5-itxに限定します。
