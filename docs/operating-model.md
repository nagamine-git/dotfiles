# 仕事の置き場所と流れ

EFG technologies (一人法人) で、人 (永峰) と AI エージェント (Claude Code / Codex) が同じ決まりで動くための表。
要点は `dot_agents/AGENTS.md` の「仕事の置き場所」にあり、全エージェントが読む。2026-10-21 決定。

## 何をどこに置くか

| もの | 置き場所 | 決まり |
|---|---|---|
| 会社のタスク | Linear (チーム EFG) | 正本はここだけ。Slack・Artifact・会話で決まったことも Linear に戻す |
| 本人にしかできない作業 | Linear: 担当 永峰、状態 In Review | 大きさでなく「人にしかできないか」で決める (権限・お金・ログイン・鍵・事業の判断)。本文は「決めること / 手順 (何分) / 終わった合図」 |
| 本人への連絡 | Slack bot «Claude (EFG)» の DM (`slack-claude dm`) | 1 日 1 回まとめて送る。作業が止まっているものだけすぐ送る |
| コードの変更 | GitHub の PR | 下の段分けに従ってマージ・デプロイ |
| KPI・滞留 | Tailscale 上の PWA ダッシュボード 1 つ | 滞留は Linear の画面で見る。ダッシュボードを増やさない |
| 一時的な確認 (比較・見本・報告) | Artifact | 残すべき結論は Linear か repo に移す |
| 個人のタスク | 野帳 (今日の分) / Google カレンダー (日付・繰り返し) | Linear に入れない |
| 個人の定期作業を AI に任せる | クラウドの定期実行、手元が要るなら am5-itx の timer で `claude -p` | お金の移動は AI がしない。人の作業は bot の DM で知らせる |

## PR の段分け

| 段 | 対象 | マージ・デプロイ |
|---|---|---|
| 自動 | ドキュメント、テスト、依存のパッチ・マイナー更新、見た目の修正、lint | CI が緑なら自動マージ・自動デプロイ |
| 本人承認 | 課金、認証・権限、データの移行・削除、鍵、本番の設定、外部への送信、費用が増える変更 | レビュー観点を固め、エージェントが指摘を解消してから本人が承認する |

迷ったら本人承認の段に置く。
